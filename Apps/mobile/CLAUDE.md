# Phone app (`Apps/mobile/`)

The rules for the whole repo are in the root CLAUDE.md.

- Phone app (`Apps/mobile/`, Expo SDK 57 / React Native, expo-router in `src/app`, its own package.json, `bun.lock` (its `bunfig.toml` keeps node_modules flat), node_modules and `bun run typecheck`; excluded from the root tsconfig and eslint; tried in Expo Go): like the extension it imports the client-safe `src/lib` modules as `@lib/…` — `metro.config.js` resolves the aliases itself (Metro's tsconfig paths are off in app.json, since tsconfig `paths` point luxon/adhan at their types) and sends bare imports from `src/lib` to the app's own node_modules. Arabic RTL in Expo Go too: a root `direction: "rtl"` view and text aligned with `START` (`src/theme/rtl.ts`; app.json also sets forcesRTL for builds), logical `start`/`end` styles only; never Alert/confirm: `Sheet` and `useDialogs()` (`src/components/sheet.tsx`; a sheet can't open a dialog over itself on iOS). The look: globals.css tokens turned from oklch into sRGB per palette (`src/theme/colors.ts`), IBM Plex Sans Arabic per weight, the logo from `logo.ts` (react-native-svg), the `public/bg` mosque scene fading night→sunset on scroll (`scene.tsx`), the site bar's three looks as the floating tab bar (`floating-bar.tsx`, `settings.nav`). State on the device (AsyncStorage): the site's `SitePrefs` changed only through `applyAction` (place, tasbeeh, khatma), the app's settings (`src/core/settings.ts`: theme, palette, nav, Asr madhab, adhan), and the Hijri offset from `GET /api/hijri-offset` (last value kept, else 0). Adhan notifications are local (expo-notifications one-off DATE triggers, `src/core/notifications.ts` `plan`, ≤56 pending for iOS's 64, rescheduled on every open and change); expo-notifications is only `require`d when used, never imported at the top of a file: Expo Go on Android (SDK 53+) throws on import, so there (`executionEnvironment` storeClient) the adhan section says it needs the dev build (expo-dev-client, `bun run android:dev` = `expo run:android`; `bun run start` is `expo start --go`; prebuild's `android/`/`ios/` are gitignored; `SCHEDULE_EXACT_ALARM` so alarms ring on time). Keep `tsconfig.json` as `expo start` writes it (plain JSON, no `.expo/types` include while typed routes are off) and pin native packages to the SDK's versions (`bunx expo install --check`; react-native-reanimated/worklets are direct deps for that). Data files: `src/lib/content/data.ts` runs unchanged — metro.config.js sends its `node:fs`/`node:path` to `src/shims/node-fs.ts`/`node-path.ts` (which gives RN a `process.cwd()`); metro.config.js writes each file of its `DATA_FILES` (hisn, quran, qcf, reciters, radios: ~2.3 MB) into `generated/data/*.js` (gitignored) as one JSON string, and the shim's `FILES` requires exactly those, so data.ts parses each once — add a file in both places to use it. Screens so far: prayer times + adhan, the azkar index and reader (`(tabs)/azkar.tsx`, `azkar/[slug].tsx`: the site's /r behaviour — `HISN_GROUPS`, `timeSuggestion`, one zikr at a time with a counter, swipe, today's progress under `reader:<slug>`, `MEMORIAL.name` line when done), tasbeeh (`TASBEEH_PHRASES`, the `tasbeeh` site action), the Hijri calendar (`hijri-core`, `withoutEmoji` on `HIJRI_EVENTS`), and the qibla (`qibla.ts` + expo-location `watchHeadingAsync`); the mushaf (`mushaf/[page].tsx`, `components/mushaf-page.tsx`: `mushafPageRows` in the page's QCF V2 font as TrueType from the same quran.com CDN — `/hafs/v2/ttf/pN.ttf`, `/surah-names/v1/sura_names.ttf`, downloaded once into the documents by `src/core/qcf-fonts.ts` — one size per page measured with `onTextLayout` so the widest line fills the frame, swipe right for the next page, the index, an ayah panel, «استمع» ayah by ayah, today's wird bar; last page in `mushaf:last`), Quran search (`searchQuran`), the khatma (the `khatma` site action, `MEMORIAL.name` line on a finished one), and audio (`src/core/player.tsx`: one expo-audio player for a whole surah from mp3quran.net going on to the next, a live station with «now playing» from `/api/radio/[id]`, or ayah by ayah from everyayah.com with the basmala before each surah but 1 and 9; background playback and lock-screen controls, speed, a sleep timer; `/recitations`, `/radio`, `/player`, and `components/mini-player.tsx` above the floating bar; offline listening: `src/core/downloads.ts` saves a recitation's surahs as `documents/recitations/<moshaf>/<NNN>.mp3` one at a time through a `.part` file, indexed under `downloads`, the player playing a saved surah from its file (`localSurahUri`), `/downloads` lists them with their size — `layout-metrics.ts` gives the bottom room, off the reader, mushaf and player pages); Amiri Quran for ayah text outside the mushaf. Never `{number && <View/>}` in JSX (a 0 renders as text and crashes): compare (`> 0`) or use a ternary. App icons: `bun run icons` (draws `assets/` with the root's canvas). Every section is listed in `src/core/sections.ts`.
