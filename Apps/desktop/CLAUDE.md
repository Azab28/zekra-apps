# Windows app (`Apps/desktop/`)

The rules for the whole repo are in the root CLAUDE.md.

- Windows app (`Apps/desktop/`, C# WinUI 3 on Windows App SDK 1.8, unpackaged, .NET 10; `Zekra.slnx`, README.md there): a tray icon and a Mica window (next prayer with a countdown, today's times, Gregorian/Hijri dates, azkar from hisn.json, qibla, settings in `%LOCALAPPDATA%\Zekra\settings.json`), the adhan window in the screen's corner (the extension's recordings copied on build from `Apps/extension/adhan`, never a second copy in git; a reminder minutes before, muted prayers; sound only over full-screen apps), a zikr window with a tasbeeh counter every so often, and the next prayer on the taskbar (Windows has no API for it: an experimental borderless window over the taskbar by the clock, or a small bar above it). The corner windows show without taking the focus and hand it back when clicked (XAML activates its window on a click whatever the styles). `Zekra.Core` has no UI: `Adhan.cs` is a line-by-line port of adhan-js 4.4.6 (the NuGet port uses older angles) and Hijri months follow the site's ICU table exported into the data (.NET's `UmAlQuraCalendar` differs before 1420 and after 1450 AH), the admin's offset from `/api/hijri-offset`. `tools/export.ts` (Node from the repo root, run by the build) writes `Data/zekra.json` (cities, methods, labels, azkar, zikr phrases as the extension's `zikrPhrases()`, the adhan dua, the logo) and the icon from `src/lib/logo.ts`, and `Zekra.Tests` compares the app with `prayer-calc.ts`/`hijri-core.ts` to the minute and the day (`dotnet test Apps/desktop/Zekra.Tests`; keep it passing when either changes). Test switches: `--test-adhan`, `--test-zikr`, `--open settings|azkar|qibla`. Installer and updates: Velopack, built by `.github/workflows/desktop-release.yml` on a `desktop-v*` tag and published to the apps' public repo `Azab28/zekra-apps` as a release tagged `desktop-vX.Y.Z` (secret `PUBLIC_MIRROR_TOKEN`; the other apps release there too: Velopack skips releases without its `releases.win.json`, and `AppsRepoSource` in Updater.cs reads the 100 latest, not GithubSource's 10); package from the build folder (`dotnet publish` drops the .pri/.xbf), ASCII `--packTitle` (vpk can't delta an Arabic-named stub). Optional account: `/api/app/auth/*` and `/api/me` with the Bearer token (kept with DPAPI in `account.bin`): the city follows the account both ways, taps are added in batches with ids. CI builds and tests it on windows-latest when `Apps/desktop/**` changes.
